# CompChemWorld 归因验收

[English](../en/compchemworld-validation.md) · [项目首页](../../README.zh.md)

CFA 对两批各 98 个试次做了只读审计。196 个试次中，62 个通过，8 个待独立复核。其余 68 个评分失败、58 个运行异常的试次，都能从原始文件中定位到运行中断、评分拒绝或两者。审计使用既有计算结果和评分记录，没有重跑模拟或验证器。

| 已定位的事件 | 试次数 |
|---|---:|
| 运行中断 | 76 |
| 评分拒绝 | 76 |
| 两者都发生 | 26 |
| 失败或异常的独立试次 | 126 |

在这 126 个试次中，规则为 95 个选出了候选根因，其中运行环境 75 个、智能体决策 11 个、验证器 9 个、题目设计 0 个。其余 31 个仍待判断责任。另有 28 个试次的首项评分诊断能对应到评分源码中的唯一位置。由此可以查明哪条条件拒绝了输入；要判断责任，还须对照公开要求和实际提交内容。

## 怎样读一条归因

- task037 的轨迹由镜像构建步骤从分片还原。提交用文字说明了适用范围，验证器却要求对应字段为布尔值。单案复核确认，公开任务没有规定这项类型要求。
- task044 的公开契约要求原子数字段为整数，提交值却是 `null`。生成器从缺失的力数据推导原子数，坐标文件中已有 304 个原子。CP2K 未收敛的报错来自题目提供的历史记录。
- 15 个试次根据模型服务配额耗尽的终止记录，改判为运行环境候选原因，原始分数均保留。task103 的模型请求先因 HTTP 429 中断，验证器随后记录缺件。task087 的 0.30 分只评价记录完整度，科学结果仍待审查。

## 跨任务自检复核

task044 的自检漏掉了嵌套字段的整数约束，task049 的自检允许嵌套对象多出字段。两项任务来源独立，都有自检实际运行的记录。将脚本与输出、公开约束和评分拒绝逐一对应后，跨案复核支持两次自检都漏查了嵌套数据约束。

task093、task170 的自检决定也获得了各自试次的证据支持。task143 的公开停止条件只写“最大原子力”，没有明确范数，仍保留为候选。上述判断限于各案受审的具体决策。[八个能力维度](taxonomy.md#agent-capability-dimensions) · [怎样复核自检](evidence-review.md#具体失败位置与自检证据)
